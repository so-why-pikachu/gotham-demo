# 场景一实施记录

## 后续交互调整

- 工作区全局标签显示“总览”；导航图标的英文提示保持 Global overview。
- 设备入口现位于 info1 → Ops → 型号收纳栏 → 个体实例，取代地图底部按钮。按设备型号动态分组，支持同型号多个实例，选中后继续打开 info2 并进行一次性相机定位。

- info1 在桌面端上移 36px；窄屏仍避让顶部导航。
- 移除底部 Global Overview 概览收纳条，保留设备选择按钮并下移到地图底部。
- 矿卡显示名称改为 XDE240；设备 ID `truck-01`、模型文件、路线和历史记录保持原样。
- 点击设备或底部按钮时，相机飞向设备被点击时的位置快照，距离约 150m。相机不绑定设备、不随车辆移动；重复点击同一设备会重新定位。复位与返回全国仍使用已有预设。
- 以上调整取代下文早期版本中“不缩放设备”和“底部矿区列表”的描述。

Global Overview 现在采用“全国 → 矿区 → 设备档案”的预制流程。矿区可通过地图标记、顶部选择框和底部矿区列表进入；设备可通过模型及辅助圆点、底部设备按钮选择。设备选择只打开右侧 info2，主动点击“进入设备诊断”才切换工作区。

左侧 info1 保留 Situations / Ops / Data，新增环境气候、施工、设备、人员、告警指标和当前 / 24h / 7 天切换。历史数据为固定模拟样例，时间范围以面板时间戳为准。其他三个矿区尚无设备与监测数据，显示未接入。

相机禁用自由旋转、平移、缩放和倾斜，仅响应预设定位。玉龙按 P1–P6 活动范围和采样地形高度定位；其他矿区使用各自观察范围。全国状态隐藏三车与路线，P1–P6 调试标记继续隐藏。设备辅助标记复用模型的动画位置和出发时间，避免尚未出发的车辆标记重叠。

切换矿区不重建 Viewer；切换工作区后恢复选择并保留本次页面会话的路线进度。刷新页面开始新的路线演示。地图资源异常时指标和设备档案仍可独立使用，地图提供错误提示。

## 接口与数据

新增 `GET /api/v1/mines/:id/metrics?range=current|24h|7d`。未知矿区返回 404，非法范围返回 400。指标为只读，不修改 `data/demo-state.json`。当前告警从设备告警记录聚合；缺失故障事件不伪装成零。

info2 复用设备遥测、告警、工单 API 和已有业务快照；快速切换会取消旧请求。宏观指标只回看数据，不回放地图历史。

## 验证

- `npm test`：原有业务 / 持久化测试与新增矿区指标测试。
- `npm run test:scene`：相机输入限制、离地构图目标、过期飞行回调、销毁取消。
- `npm run test:fleet`：实际路线坐标上的合成地形运动验证，原三车错峰和停靠保持不变。
- `npm run test:scene:browser`：需启动本地 dev 和 CDP 9345 的浏览器，或用 `DEMO_URL` / `CDP_PORT` 指定。验证原生鼠标设备选择、历史切换、缺测状态、返回全国及 1920 / 1440 / 1280 布局；截图保存到系统临时目录。

浏览器面板测试主动屏蔽外部网络，不能据此宣称在线地形和模型拾取已经验收。在线环境还需检查：飞入玉龙后路线和三车位于左右面板之间；模型 / 辅助标记点击打开对应设备；滚轮和拖拽不改变相机；返回全国只显示矿区标记。当前不需要新增 Blender 资产或 Docker 服务。
