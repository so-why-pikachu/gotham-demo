# 场景一优化方案：矿区态势与设备档案

状态：待实施。本文件只定义方案，不代表功能已上线。

依据：`scene-polish.md` 的场景一，以及 `picture/gotham.png`、`picture/info2.png`。本次范围为宏观指标、预制相机流程和设备浮层；场景二、三保持已有业务入口。

## 1. 最终体验

用户进入 Global Overview 后看到固定的全国俯瞰图。点击矿区标记，地图自动飞入该矿区的设备分布视角，左侧原有 info1 展示矿区宏观信息。点击设备，右侧打开 info2 设备档案浮层，地图和 info1 保持可见，不自动跳转工作区，也不继续放大相机。

返回全国只需点击一个按钮。全过程不要求拖动、滚轮缩放或组合键操作。

```text
│ 全国 / 玉龙矿区                    返回全国  复位视角 │

│ │宏观指标 / 趋势    │设备与路线 │当前参数 / 趋势   │ │
│ │折叠信息栏         │           │设备关联 / 工单   │ │
│ └──────────────────┘           │进入设备诊断      │ │
│                                └──────────────────┘ │
│ 原有底部概览抽屉（默认收起）                         │
└────────────────────────────────────────────────────┘
```

- 保留顶部导航、标签栏、底部抽屉和地图主体；新增浮层不改变工作区结构。
- 复用 `App.css` 的深灰蓝背景、蓝灰细边框、MiSans 字体和现有 3–4px 圆角。主色使用已有 `--accent`，告警使用已有 warning / danger 色。
- info1 延续蓝色折叠栏、紧凑数据行；info2 参考图中的文档标题、元数据、关联关系和内容分节。正文约 12–13px，面板标题约 14–16px。
- 指标采用双列数值行与小型趋势线，不占用地图铺设大型 KPI 卡片。日期、单位、数据来源靠近指标。
- info2 默认宽 340px，建议最大高 `min(680px, 可用地图高度 - 28px)`；内部滚动，底部操作固定。它是侧边小浮层，不是居中模态框，也不是第二个全屏 Inspector。
- 1440px 及以上左右面板并列；1280px 时 info1 约 300px、info2 约 320px，地图中部至少保留约 600px。更窄时打开 info2 自动将 info1 收成标题条，关闭后恢复。
- 相机预设按左右面板占位计算可视安全区，关键设备和路线不能落在面板下面；关闭 info2 不触发新的相机飞行。
- 底部概览抽屉展开时相应压缩浮层最大高度，保留地图归属信息的可见位置。

## 4. info1：新增宏观指标

全国状态下默认不展开大面板，保留干净地图。选中矿区后显示 info1；标题明确矿区名称和“模拟数据”，元数据改为快照时间、施工状态及数据覆盖情况。

### 4.1 三个原有标签的职责

| 原有标签 | 默认展示 | 可展开内容 |
| --- | --- | --- |
| Situations：态势 | 施工状态、设备运行概览、人员在岗、告警摘要 | 环境与气候、故障趋势、当前异常 |
| Ops：作业 | 施工单位、工况构成、设备类型数量 | 型号分布、作业区域分布、施工进度 |
| Data：数据 | 指标历史、数据时间与来源 | 环境传感器记录、缺测说明、覆盖率 |

原有折叠栏可调整为“矿区概况 / 环境与气候 / 设备与施工 / 人员与故障”，不继续使用无业务对应的固定文案。

### 4.2 指标与口径

| 指标组 | 第一版字段 | 展示与统计规则 |
| --- | --- | --- |
| 环境传感器 | 粉尘浓度、噪声、传感器在线数 / 总数 | 标明 mg/m³、dB、采样时刻；没有配置阈值时不自行判定超标 |
| 气候 | 气温、湿度、风速、降水 | 使用标注来源的模拟气象快照，不能描述为在线天气 |
| 施工主体 | 施工单位、班次、施工区域 | 展示名称与负责范围；施工单位和设备客户分别建字段 |
| 机械分布 | 设备总数、类型 / 型号计数、区域分布 | 按设备 ID 去重；玉龙当前为矿卡、挖掘机、装载机各一台 |
| 工况与状态 | 运输 / 挖装 / 装载、作业 / 待机 / 检修 | 工况、运行状态、健康告警分别建模，不能从 warning 推断设备停工 |
| 人员 | 在岗人数、班组数 | 数值为明确的新增 Mock 样例，不由设备数量推算 |
| 故障 | 活跃告警条数、受影响设备数、统计期内故障事件数 | 一台设备可有多个告警；故障事件与一般告警分开计数 |

### 4.3 当前与历史

- 面板内提供“当前 / 近 24h / 近 7 天”。当前显示最新快照；历史显示所选区间的小型折线和汇总。
- 第一版使用确定性的模拟时间序列，不在每次请求时随机变化；显示实际样例日期范围，避免把固定历史数据标为今天。
- 当前人数为最近一次在岗快照；历史人数显示均值 / 峰值，不把每日人数相加。告警区分区间新增和快照活跃，设备总数使用期末去重数。
- 图表标明单位和样本时间，缺失数据用断点或“未接入”，不显示虚假的 0。不同物理量不共用无单位的纵轴。
- 切换时间范围只改变指标，不回放三车、不重置场景时钟。历史地图回放不属于第一版。
- 其他三个矿区暂未接入设备时，设备数显示“未接入”；全国汇总称为“已接入设备 3 台”，不能称为四矿全部设备总量。

## 5. 相机：两级观察、三级交互状态

只有全国、矿区两种相机尺度；设备详情是矿区尺度内的选择状态，不增加设备近景一级。

| 状态 | 地图与面板 | 允许的操作 |
| --- | --- | --- |
| NATIONAL | 固定全国俯瞰；只显示矿区标记，名称 hover 显示 | 点击矿区、从矿区列表选择 |
| ENTERING_MINE | 飞向所选锚点，显示轻量定位提示 | 返回全国、选择另一矿区；暂不响应设备点击 |
| MINE | 固定矿区设备分布图，展开 info1 | 选择设备、复位视角、返回全国 |
| EQUIPMENT_SELECTED | 原矿区视角 + 右侧 info2 + 设备高亮 | 切换设备、关闭详情、主动进入诊断 |
| RETURNING_NATIONAL | 关闭 info2、清除选择并返回全国 | 新的矿区定位请求可取代旧请求 |

### 5.1 禁用和保留的输入

- 禁用鼠标拖拽平移、滚轮缩放、中键倾斜、自由旋转，以及触屏对应的相机手势；移除默认双击跟踪行为。
- 保留设备与矿区拾取、名称 hover，以及面板自己的滚动；不在整个页面拦截键鼠事件。
- 相机只接受预设定位命令。“复位视角”回到当前矿区预设，“返回全国”返回全国预设。
- 设备点击不能设置自动跟随目标，不能触发 flyTo；相机不会追随矿卡移动。
- 为矿区列表和设备列表提供等价按钮入口，保证键盘用户也能完成流程。

### 5.2 预设构图

- 全国：以现有 `CHINA_VIEW` 为起点，北朝上、俯角 -90°。根据视口比例校准覆盖范围，不把当前 240 万米高度当作所有尺寸的最终值。
- 玉龙：以 P1–P6 运输区域和三台设备完整活动范围的包围范围为构图目标，而非只对准矿区标记点。方位固定、俯角先以 -65° 至 -75° 调校，保留地形与车型辨识。
- 矿区观察距离依据活动范围、相机视场角、面板占位和地形高度计算，再保存为可复用预设；不能直接把统一海拔当作离地高度。定位后设备既能辨识，也能点击。
- 其他矿区配置独立中心、范围与相机方位；没有设备坐标时展示矿区范围和“设备分布未接入”。不复制玉龙设备到其他矿区。
- 预计飞行约 1.6–2.2 秒，减弱动态效果偏好下缩短或直接定位。最终时长以目标机器视觉验证为准。
- 使用请求序号和取消机制管理连续点击，旧飞行动画完成回调不能覆盖新选择。窗口尺寸变化仅重新校准当前预设，避免持续追踪式抖动。

### 5.3 设备与标记可见性

- 全国状态隐藏路线、设备模型及设备标签，继续隐藏 P1–P6 调试标记。
- 矿区定位结束后，只展示该矿区设备与路线；名称仅 hover 或选中显示。
- 设备保持现有三车路线、0 / 12 / 24 秒出发差、P6 / P5 / P4 停靠逻辑。显示层切换不重新初始化车队，不重置路线时钟。
- 俯瞰尺度下为设备增加小型、统一 Gotham 样式的可点击标记，命中区域约 24–32px，和模型映射同一个 equipmentId。标记位置取当前动画位置，而非写死初始经纬度。
- 选中效果使用细蓝色轮廓或定位环，不改变设备业务状态色；关闭 info2 后取消高亮。

## 6. info2：当前地图内的设备档案

采用 `info2.png` 的右侧文档式浮层结构，但内容改为设备业务：

1. 标题：设备图标、设备名称、设备 ID、健康状态与关闭按钮。
2. 基础档案：型号、设备类型、所属矿区、客户 / 施工单位、累计工作小时、快照时间。
3. 当前参数：对应型号的温度 / 压力 / 压差等已有遥测，标明字段、值、单位和采样时刻；只展示该设备已具备的参数。
4. 小型趋势：最近 12 个遥测样本；默认仅画一个指标，不把温度和压力混在一条轴上。
5. 关联关系：设备为中心，连接“所属矿区 / 所属客户 / 最近工单 / 最新诊断报告”。使用少量静态 SVG 或 DOM 节点即可，不引入新的图谱库。不存在的关系显示未关联，不虚构联系人或组织。
6. 告警与维修：最近告警、最近 2–3 条工单，展开查看摘要。
7. 底部操作：“进入设备诊断”。仅用户主动点击后调用既有 Operations 工作区入口，携带实际 equipmentId 和 mineId。

交互规则：同一时刻只开一个 info2；选择另一设备原位替换内容；点击地图空白或关闭按钮只关闭 info2，保留矿区和 info1。“返回全国”同时关闭两个面板。“关闭 info1”只隐藏左栏，提供重新展开入口，不改变视角。

数据请求按设备取消和去重，防止快速切换时旧设备结果覆盖新设备。面板显示加载骨架、无记录、失败重试三种状态；API 失败不导致地图卸载。

## 7. 数据与接口改造

继续使用当前 Node Mock 后端，不新增数据库服务或 Docker 容器。

### 7.1 复用现有接口

- `GET /api/v1/mines`：矿区目录。
- `GET /api/v1/equipment?mineId=...`：矿区设备清单。
- `GET /api/v1/equipment/:id`：设备档案。
- `GET /api/v1/equipment/:id/telemetry`：遥测样例。
- `GET /api/v1/equipment/:id/alerts`、`work-orders`：设备告警与工单。
- 已加载的报告快照用于关联最新诊断，避免另外生成报告。

### 7.2 建议新增接口（目前不存在）

- `GET /api/v1/mines/:id/metrics?range=current|24h|7d`：返回矿区宏观快照、统计期、分组指标、趋势和覆盖情况。
- 响应字段建议为 `mineId / mock / asOf / period / coverage / summary / environment / weather / operations / workforce / faults / series`。
- 指标结构统一携带 `value / unit / sampledAt / source / availability`；availability 区分 available、missing、not-connected。
- 快照和历史序列由独立 Mock 种子文件提供，人员、天气、施工主体等新增样例明确归属于模拟数据；已有设备和告警数量由共同的设备 / 告警源聚合。
- 第一版不把这些只读指标写入 `data/demo-state.json`，避免覆盖既有报告和推送记录。指标刷新也不重置演示进度。
- 锚点先保留为前端静态配置；矿区 ID 与后端目录保持一致，区分业务档案字段与相机表现字段。

## 9. 实施顺序与验收

1. 先完成预设相机和导航状态：四矿定位、返回全国、连续操作取消、禁用自由视角。先把路线和面板安全区对齐，再扩展内容。
2. 接入 info1 的宏观快照和历史；补接口类型与后端聚合，核对指标口径。
3. 接入 info2、设备辅助拾取标记和局部选中效果，移除设备点击的自动跳页。
4. 在 1920×1080、1440×900、1280×800 做布局与在线地形验证，最后回归三车路线和报告业务。

验收清单：

- 全国视角没有 P1–P6、设备或常驻矿区文字；矿区 hover 显示名称。
- 不使用拖拽或滚轮即可完成全国 → 玉龙 → 设备 → 返回全国；键盘通过等价按钮也能完成。
- 相机停在预设设备分布视角，三台车全程处于可观察区域，点击设备不开新标签、不继续缩放。
- 左右浮层符合 Gotham 原布局，中央设备不被遮挡，面板滚动不改变地图相机。
- 三种设备 info2 展示各自数据；快速切换不串数据，关闭后仍处于同一矿区。
- 连续选择 A、B 矿区或飞行中返回全国，最终视角与 UI 选择一致；切换工作区后恢复已完成的观察状态，不重放过期飞行。
- 当前与历史指标有时间、单位、来源；设备数与清单一致，其他矿区缺测不伪装成 0。
- 场景二的主动诊断入口和现有商业报告流程可用；三车错峰与停靠点保持不变。
- 执行类型检查、构建、后端指标接口测试、导航状态测试和浏览器原生点击验证；路线表现相关文件有变动时执行现有车队测试。
- 浏览器截图 / 配置放系统临时目录；仅保留必要的测试脚本，避免再次在 Git 库生成浏览器缓存。
